Self-Hosting Your Recipe Collection with Docker and CookCLI

February 25, 2026 · Updated November 19, 2026

If you keep your recipes in Cooklang format, you can serve them on your local network with a single Docker command. CookCLI runs a lightweight web server that lets you browse, search, and generate shopping lists from any device — phone, tablet, or laptop.

No cloud account. No subscription. Your recipes stay on your hardware.

Quick Start#

If you already have Docker installed:

docker run -d \
  --name cookcli \
  --restart unless-stopped \
  -p 9080:9080 \
  -v /path/to/your/recipes:/recipes \
  ghcr.io/cooklang/cookcli:latest

Replace /path/to/your/recipes with the directory containing your .cook files. Open http://localhost:9080 in a browser and you're done.

Docker Compose Setup#

For a more maintainable setup, create a docker-compose.yml:

services:
  cookcli:
    image: ghcr.io/cooklang/cookcli:latest
    ports:
      - &#34;9080:9080&#34;
    volumes:
      - ./recipes:/recipes
    restart: unless-stopped

Then:

docker compose up -d

Put your .cook recipe files in the ./recipes directory. The server picks them up automatically — no restart needed when you add new recipes.

What the Server Does#

The web interface at http://localhost:9080 provides:

  • Recipe browsing — folder-based navigation that mirrors your directory structure
  • Search — find recipes by name or ingredient
  • Recipe scaling — adjust serving sizes and all ingredient quantities update
  • Shopping lists — select multiple recipes, set individual serving counts, and generate a combined list organized by store aisle
  • Pantry tracking — mark what you already have, and shopping lists exclude those items
  • Mobile-friendly — responsive layout works on phones and tablets

The web UI can also create and edit recipes, and it writes pantry and shopping-list changes to the mounted folder. By default anyone who can reach the server can make those changes. To require sign-in, add a user with cook server user add <name>; the CookCLI README has a section on doing that in a container.

Accessing from Other Devices#

By default, CookCLI's Docker image binds to all interfaces (--host), so it's accessible from any device on your local network.

Find your server's IP address:

# macOS
ipconfig getifaddr en0

# Linux
hostname -I | awk &#39;{print $1}&#39;

Then open http://192.168.1.100:9080 (your IP will differ) from your phone or tablet. Opening the server by host name instead (for example http://nas.local:9080) needs that address in a COOK_CORS_ORIGIN environment variable; IP addresses work without it.

Organizing Recipes for the Server#

The server displays your folder structure as navigation. A clean directory layout makes browsing easier:

recipes/
├── config/
│   └── aisle.conf
├── Breakfast/
│   ├── pancakes.cook
│   └── overnight-oats.cook
├── Dinner/
│   ├── Quick Weeknight/
│   ├── Weekend Projects/
│   └── Batch Cooking/
├── Desserts/
├── Sides/
└── Basics/
    ├── chicken-stock.cook
    └── pizza-dough.cook

Aisle Configuration#

Add a config/aisle.conf file inside your recipe directory to organize shopping lists by store section:

[Produce]
tomato|tomatoes
onion|onions
garlic
lettuce
bell pepper|bell peppers

[Dairy]
milk
butter
cheese
cream
eggs

[Meat]
chicken
beef
pork

[Pantry]
olive oil
salt
pepper
flour
sugar
rice
pasta

[Spices]
cumin
paprika
oregano
chili flakes

Ingredients matching these patterns get grouped by aisle in your shopping list. The | syntax handles plurals and alternate names.

Syncing Recipes to the Server#

Git (Recommended)#

Mount a Git repository as the recipe volume:

# On the server
git clone https://github.com/yourusername/cookbook.git /home/user/recipes

Set up a cron job or systemd timer to pull updates:

# Pull every 30 minutes
*/30 * * * * cd /home/user/recipes &amp;&amp; git pull --quiet

Recipes you push from your laptop appear on the server within 30 minutes.

Syncthing#

For real-time sync without Git, Syncthing runs well alongside the recipe server:

services:
  cookcli:
    image: ghcr.io/cooklang/cookcli:latest
    ports:
      - &#34;9080:9080&#34;
    volumes:
      - recipes:/recipes
    restart: unless-stopped

  syncthing:
    image: syncthing/syncthing
    ports:
      - &#34;8384:8384&#34;
      - &#34;22000:22000&#34;
    volumes:
      - recipes:/var/syncthing/recipes
    restart: unless-stopped

volumes:
  recipes:

Edit a recipe on your phone or laptop and it appears on the server immediately.

Running on a VPS#

If you want to access your recipes outside your home network, deploy to any VPS provider. A $5/month server handles this easily. Add a reverse proxy for HTTPS:

server {
    server_name recipes.example.com;

    location / {
        proxy_pass http://localhost:9080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

The server refuses host names it has not been told about, so add the public address to the compose service:

    environment:
      COOK_CORS_ORIGIN: https://recipes.example.com

Add Let's Encrypt with certbot for TLS, and add a sign-in user so visitors can't edit your recipes. Then you have a recipe server you can reach from anywhere.

Resource Usage#

CookCLI is a single Rust binary. It uses minimal resources:

  • Memory: around 5–12 MB with the small sample collection
  • CPU: Negligible — it's serving text files
  • Disk: The Docker image is about 45 MB to download (about 110 MB unpacked). Your recipes are plain text, so even thousands of recipes use very little space.

It runs well on a Raspberry Pi (64-bit OS for the Docker image), an old laptop, a NAS, or any VPS.

Comparison with Other Self-Hosted Options#

If you're evaluating self-hosted recipe managers, CookCLI's server is the simplest option — no database, no configuration, just point it at a directory. For a database-backed app with a richer web UI (drag-and-drop meal calendars, household accounts, in-browser recipe scraping), see our comparison of open source recipe managers.

The trade-off is clear: CookCLI gives you simplicity and data portability (plain text files). Database-backed tools like Mealie and Tandoor give you richer features at the cost of more infrastructure.
